================================================================================
                        DATASET DESCRIPTIONS
              Data Scientist Agent — Synthetic Retail Data
================================================================================

This document describes the 12 CSV datasets generated by the synthetic data
pipeline. All files include ~5% intentional dirty data (nulls, mixed casing,
whitespace) for cleaning pipeline validation.

Generated by: backend/scripts/generate_synthetic_data.py
Updated by:   backend/scripts/simulate_update.py


================================================================================
1. DATASET DESCRIPTIONS
================================================================================


--------------------------------------------------------------------------------
customers.csv — Customer Master Data
--------------------------------------------------------------------------------

Description:
  Contains demographic and account-level information about customers.

Fields:
  - customer_id       (Primary Key)    Unique customer identifier (e.g. CUST1000)
  - name              (string)         Full name (e.g. "Sarah Johnson")
  - email             (string)         Email address derived from name
  - age               (integer)        Customer age (18–70)
  - gender            (string)         Male, Female, Non-binary, Prefer not to say
  - location          (string)         City and country (e.g. "New York, USA")
  - device_type       (string)         Primary device: mobile, desktop, tablet
  - loyalty_status    (string)         Tier: bronze, silver, gold, platinum
  - total_spend       (float)          Lifetime spend computed from transactions
  - acquisition_date  (datetime)       Account creation timestamp

Primary Use Cases:
  - Customer segmentation
  - Customer Lifetime Value (CLV) analysis
  - Retention modeling
  - Personalization insights


--------------------------------------------------------------------------------
products.csv — Product Catalog Data
--------------------------------------------------------------------------------

Description:
  Stores product-level attributes, pricing details, and brand information.

Fields:
  - sku               (Primary Key)    Stock Keeping Unit (e.g. SKU10000)
  - product_name      (string)         Realistic product name (e.g. "Sony WH-1000XM5 Headphones")
  - category          (string)         One of: Electronics, Clothing, Beauty, Sports, Books, Home, Toys, Food
  - brand             (string)         Real brand name mapped to category
  - cost_price        (float)          Wholesale cost
  - retail_price      (float)          Selling price
  - profit_margin     (float)          (retail_price - cost_price) / retail_price
  - discount_percent  (float)          Active discount percentage (0–30%)
  - average_rating    (float)          Customer rating (1.0–5.0)

Primary Use Cases:
  - Revenue analysis
  - Category performance tracking
  - Margin optimization
  - Demand forecasting


--------------------------------------------------------------------------------
inventory.csv — Inventory & Stock Levels
--------------------------------------------------------------------------------

Description:
  Tracks current stock quantities, reorder thresholds, and warehouse assignments.

Fields:
  - sku                (Foreign Key -> products)   Product identifier
  - stock_quantity     (float)                     Current units in stock
  - reorder_level      (float)                     Threshold triggering reorder
  - warehouse_location (string)                    Warehouse code (e.g. WH-NY)
  - supplier           (string)                    Supplier/distributor name

Primary Use Cases:
  - Stock-out risk detection
  - Replenishment planning
  - Inventory optimization
  - Supplier performance analysis


--------------------------------------------------------------------------------
transactions.csv — Order-Level Sales Data
--------------------------------------------------------------------------------

Description:
  Each row represents a line item from a completed customer transaction.
  Transactions are derived from converted sessions.

Fields:
  - order_id          (Primary Key)                 Order identifier (e.g. ORD5000)
  - customer_id       (Foreign Key -> customers)    Purchasing customer
  - sku               (Foreign Key -> products)     Purchased product
  - quantity          (float)                       Units purchased (1–5)
  - unit_price        (float)                       Price per unit at time of sale
  - total_amount      (float)                       quantity * unit_price
  - discount_amount   (float)                       Discount applied to this line
  - order_status      (string)                      delivered, shipped, processing, cancelled, returned
  - order_datetime    (datetime)                    Timestamp of order placement

Primary Use Cases:
  - Revenue KPI computation
  - Customer spend analysis
  - Sales forecasting
  - Basket analysis


--------------------------------------------------------------------------------
transactions_with_session.csv — Transactions with Session Attribution
--------------------------------------------------------------------------------

Description:
  Enhanced transaction dataset linking orders to the website session that
  generated them. Contains all fields from transactions.csv plus session_id.

Additional Field:
  - session_id        (Foreign Key -> sessions)     Originating session

Primary Use Cases:
  - Conversion attribution
  - Revenue per session analysis
  - Channel performance evaluation


--------------------------------------------------------------------------------
payments.csv — Payment Processing Data
--------------------------------------------------------------------------------

Description:
  Contains payment-level information associated with each order.

Fields:
  - order_id          (Foreign Key -> transactions)  Associated order
  - payment_method    (string)                       credit_card, debit_card, paypal, wallet, bank_transfer
  - payment_status    (string)                       completed, pending, failed, refunded
  - transaction_fee   (float)                        Processing fee charged
  - currency          (string)                       Payment currency (USD, EUR, GBP, etc.)

Primary Use Cases:
  - Payment method performance analysis
  - Net revenue calculation
  - Transaction monitoring
  - Multi-currency reporting


--------------------------------------------------------------------------------
marketing.csv — Marketing Campaign Metadata
--------------------------------------------------------------------------------

Description:
  Stores campaign-level metadata including budget and high-level performance
  metrics for marketing initiatives.

Fields:
  - campaign_id       (Primary Key)    Campaign identifier (e.g. CAMP3000)
  - channel           (string)         email, google_ads, facebook, instagram, in_app, social
  - campaign_type     (string)         seasonal_sale, new_arrival, clearance, loyalty, flash_sale
  - campaign_name     (string)         Descriptive name (e.g. "Summer Blowout 2026")
  - start_date        (date)           Campaign start
  - end_date          (date)           Campaign end
  - ad_spend          (float)          Total budget spent
  - impressions       (float)          Total ad impressions
  - clicks            (float)          Total clicks received
  - conversions       (float)          Total conversions attributed

Primary Use Cases:
  - Marketing spend analysis
  - Customer acquisition cost (CAC) estimation
  - Campaign ROI measurement


--------------------------------------------------------------------------------
campaign_performance.csv — Daily Campaign Performance
--------------------------------------------------------------------------------

Description:
  Provides daily breakdown of marketing performance per campaign and channel.

Fields:
  - date              (date)                          Calendar date
  - campaign_id       (Foreign Key -> marketing)      Associated campaign
  - channel           (string)                        Marketing channel
  - campaign_name     (string)                        Campaign display name
  - impressions       (float)                         Daily impressions
  - clicks            (float)                         Daily clicks
  - spend             (float)                         Daily spend
  - sessions          (float)                         Sessions attributed to campaign
  - orders            (float)                         Orders attributed to campaign
  - attributed_revenue (float)                        Revenue attributed to campaign

Primary Use Cases:
  - ROAS calculation
  - Budget allocation optimization
  - Channel-level forecasting


--------------------------------------------------------------------------------
sessions.csv — Session-Level Website Data
--------------------------------------------------------------------------------

Description:
  Each row represents a complete user session on the website. Sessions are
  the central link between customers, events, and transactions.

Fields:
  - session_id         (Primary Key)                  Session identifier (e.g. SESS100000)
  - customer_id        (Foreign Key -> customers)     Visiting customer
  - session_start      (datetime)                     Session start timestamp
  - session_end        (datetime)                     Session end timestamp
  - session_duration_sec (float)                      Duration in seconds (30–1800)
  - pages_viewed       (float)                        Number of pages viewed (1–20)
  - device_type        (string)                       Device used: mobile, desktop, tablet
  - landing_page       (string)                       Entry page: home, product, category, deals, new_arrivals, search
  - traffic_source     (string)                       organic_search, paid_search, email, social, direct, referral
  - campaign_name      (string)                       Attributed campaign (null if organic/direct)
  - converted_flag     (boolean)                      Whether session resulted in a purchase
  - revenue            (float)                        Revenue generated (0 if not converted)

Primary Use Cases:
  - Conversion rate calculation
  - Revenue per session analysis
  - Channel attribution
  - Traffic performance monitoring
  - Device-based analytics


--------------------------------------------------------------------------------
events.csv — Event-Level User Actions
--------------------------------------------------------------------------------

Description:
  Granular user interactions captured within sessions. Events follow a
  realistic funnel: page_view -> product_view -> add_to_cart -> begin_checkout
  -> purchase. Not every session reaches all stages.

Fields:
  - event_id           (Primary Key)                  Event identifier (e.g. EVT200000)
  - session_id         (Foreign Key -> sessions)      Parent session
  - customer_id        (Foreign Key -> customers)     Acting customer
  - event_type         (string)                       page_view, product_view, add_to_cart, begin_checkout, purchase
  - event_datetime     (datetime)                     Timestamp of the event
  - sku                (Foreign Key -> products)      Product involved (null for page_view)
  - quantity           (float)                        Units (null for view events)
  - unit_price         (float)                        Price at time of event (null for page_view)

Funnel Drop-off Rates:
  - page_view:      100% of sessions
  - product_view:   ~70% of sessions
  - add_to_cart:    ~30% of sessions
  - begin_checkout: ~15% of sessions
  - purchase:       only converted sessions (~20%)

Primary Use Cases:
  - Add-to-cart rate analysis
  - Checkout abandonment analysis
  - Behavioral feature engineering
  - Demand modeling inputs


--------------------------------------------------------------------------------
web_analytics.csv — Raw Website Activity Log
--------------------------------------------------------------------------------

Description:
  Captures low-level website interaction data from the platform. Each row
  is a distinct user action on the site.

Fields:
  - event_id           (Primary Key)                  Web event identifier (e.g. WEB300000)
  - session_id         (Foreign Key -> sessions)      Associated session
  - customer_id        (Foreign Key -> customers)     Acting customer
  - event_datetime     (datetime)                     Timestamp of interaction
  - page_type          (string)                       home, product, category, cart, checkout, search_results
  - action             (string)                       view_page, add_to_cart, remove_from_cart, purchase, search
  - add_to_cart        (boolean)                      Whether action was an add-to-cart
  - referral_source    (string)                       direct, organic_search, email, social, paid_ads

Primary Use Cases:
  - Behavioral tracking
  - Session reconstruction
  - Funnel analysis


--------------------------------------------------------------------------------
funnel_summary.csv — Daily Funnel Metrics
--------------------------------------------------------------------------------

Description:
  Aggregated daily funnel statistics derived from session and event data.
  One row per calendar day across the 12-month data window.

Fields:
  - date                  (date)     Calendar date
  - sessions              (float)    Total sessions that day
  - product_views         (float)    Product view events
  - add_to_cart           (float)    Add-to-cart events
  - checkout_started      (float)    Begin-checkout events
  - purchases             (float)    Purchase events
  - conversion_rate       (float)    purchases / sessions
  - cart_abandonment_rate (float)    1 - (purchases / add_to_cart)

Primary Use Cases:
  - Funnel drop-off monitoring
  - UX performance tracking
  - Early operational risk detection


================================================================================
2. DATASET RELATIONSHIPS
================================================================================

The datasets are connected across multiple analytical layers:

Customer Layer:
  customers -> sessions -> events -> transactions

Product Layer:
  products -> events -> transactions -> inventory

Marketing Attribution Layer:
  marketing -> campaign_performance -> sessions -> transactions

Behavioral Analytics Layer:
  web_analytics -> sessions -> events

Aggregated Analytics Layer:
  events + sessions -> funnel_summary

Session-Transaction Link:
  sessions -> transactions_with_session (= transactions + session_id)

Payment Layer:
  transactions -> payments


================================================================================
3. DATA GENERATION & UPDATE
================================================================================

Initial Generation:
  python scripts/generate_synthetic_data.py
  - Produces all 12 CSVs with seed=42 for reproducibility
  - 500 customers, 200 products, 8000 sessions, ~4300 transactions
  - 12-month window ending Feb 15, 2026

Incremental Updates (with dynamic scenarios):
  python scripts/simulate_update.py --days 7 --scenario <name>

  Available scenarios:
    organic-growth    Steady healthy growth (default)
    profit            High conversions, strong margins, low returns
    loss              Low conversions, high returns/cancellations
    seasonal-spike    Holiday/flash sale: 4x volume, heavy discounts
    stockout-crisis   Supply chain problems, inventory drain
    marketing-blitz   5x ad spend, flood of paid traffic
    churn-wave        Customer exodus, low engagement
    new-product-launch  Concentrated demand on newest products
